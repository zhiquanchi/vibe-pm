# PRD-02：项目成员与权限

> 版本：v1.0 Draft  
> 日期：2026-08-07  
> 状态：待评审  
> 上游依赖：PRD-01 项目与阶段基础

## 1. 概述

定义项目负责人、阶段负责人、成员和观察者四类职责，确保阶段配置、任务维护和阶段验收由正确的人执行。

## 2. 目标

- 项目访问和关键写操作具有明确权限边界。
- 阶段负责人只在被分配阶段拥有阶段级管理权限。
- UI 权限状态与后端授权结果保持一致。

## 3. 角色定义

| 角色 | 主要权限 |
|---|---|
| 项目负责人 | 管理项目、阶段结构、成员、主阶段及全部阶段验收 |
| 阶段负责人 | 管理指定阶段并处理该阶段验收 |
| 成员 | 维护有权访问的任务、阻塞和交付物 |
| 观察者 | 只读查看项目、阶段、任务和活动 |

阶段负责人是一项阶段职责，不替代成员的项目角色。

## 4. 用户故事

### US-001：查看项目成员

**Description:** 作为项目成员，我希望查看成员和职责，以便知道项目中的责任分工。

**Acceptance Criteria:**

- [ ] 成员页展示姓名、邮箱、项目角色和负责阶段。
- [ ] 支持按角色和阶段筛选成员。
- [ ] 观察者可以查看成员列表。
- [ ] 非项目成员访问时显示无权限页面。
- [ ] 在浏览器中验证列表、筛选和无权限状态。

### US-002：管理项目成员

**Description:** 作为项目负责人，我希望添加、移除成员并调整角色，以便控制项目协作范围。

**Acceptance Criteria:**

- [ ] 创建项目时必须指定至少 2 名项目负责人。
- [ ] 创建向导提示"建议指定 PM 和技术负责人作为项目负责人"。
- [ ] 项目负责人可通过用户标识或邮箱添加成员。
- [ ] 重复添加返回明确中文提示。
- [ ] 项目负责人可在成员和观察者之间调整项目角色。
- [ ] 移除仍负责阶段或任务的成员时阻止操作并展示影响范围。
- [ ] 项目负责人总数不能少于 2 人，移除时若剩余不足 2 人则阻止操作。
- [ ] 错误提示："项目至少需要 2 名项目负责人以确保验收独立性"。
- [ ] 成员变化生成活动记录。
- [ ] 在浏览器中验证添加、改角色、移除限制和错误反馈。

### US-003：分配阶段负责人

**Description:** 作为项目负责人，我希望为阶段指定负责人，以便明确阶段验收责任。

**Acceptance Criteria:**

- [ ] 每个阶段可指定一名项目成员为阶段负责人。
- [ ] 阶段启动前必须已有阶段负责人。
- [ ] 更换负责人时展示未完成验收和任务影响。
- [ ] 阶段负责人只能处理自己负责阶段的阶段级操作。
- [ ] 负责人变化生成活动记录。
- [ ] 在浏览器中验证分配、更换和权限限制。

### US-004：执行服务端权限校验

**Description:** 作为项目负责人，我希望服务端保护项目资源，以便隐藏按钮无法被绕过。

**Acceptance Criteria:**

- [ ] 所有项目资源读取均校验项目成员关系。
- [ ] 所有写接口均按项目角色和阶段职责校验。
- [ ] 无读取权限返回 403，资源不存在返回 404。
- [ ] UI 根据同一权限模型展示可用、只读或禁用状态。
- [ ] 权限矩阵自动化测试通过。

## 5. 功能需求

- FR-1：系统必须支持项目负责人、成员和观察者项目角色。
- FR-2：系统必须支持为阶段指定阶段负责人。
- FR-3：系统必须限制只有项目负责人管理成员和项目角色。
- FR-4：系统必须保证项目至少存在 2 名项目负责人。
- FR-5：系统必须限制阶段负责人只能处理其负责阶段的阶段级操作。
- FR-6：系统必须限制观察者执行写操作。
- FR-7：系统必须校验所有项目资源的成员关系。
- FR-8：系统必须记录成员、角色和阶段负责人变化。
- FR-9：系统必须在项目创建时强制指定至少 2 名项目负责人。

## 6. 非目标

- 不实现完全自定义角色或逐字段权限。
- 不实现企业组织架构、用户组、SSO 或外部目录同步。
- 不实现临时访问链接和公开项目。

## 7. 成功指标

- 权限矩阵自动化测试覆盖率为 100%。
- 未授权写操作成功数量为 0。
- 100% 的项目具有至少 2 名项目负责人。
- 项目负责人数量少于 2 人的异常数据数量为 0。

## 8. 开放问题

- 首版是否允许一个阶段同时有多名阶段负责人？当前默认只允许一名。
