# PRD-05：阶段交付物与验收

> 版本：v1.0 Draft  
> 日期：2026-08-07  
> 状态：待评审  
> 上游依赖：PRD-01、PRD-02、PRD-03、PRD-04

## 1. 概述

通过阶段交付物和负责人验收区分“任务已经完成”与“阶段目标已经达成”，形成开发阶段的正式结束机制。

## 2. 目标

- 每个阶段可以定义并提交明确交付物。
- 阶段只有满足必需条件后才能提交验收。
- 验收确认和驳回均可追溯。
- 已完成阶段受到一致的只读保护。

## 3. 用户故事

### US-001：定义阶段验收条件

**Description:** 作为阶段负责人，我希望定义必需任务和交付物，以便明确阶段完成标准。

**Acceptance Criteria:**

- [ ] 阶段负责人可将阶段任务标记为验收必需或可选。
- [ ] 阶段负责人可添加必需或可选交付物要求。
- [ ] 验收条件变更展示影响并生成活动记录。
- [ ] 阶段进入待验收后不能修改验收条件。
- [ ] 在浏览器中验证条件配置和锁定状态。

### US-002：提交阶段交付物

**Description:** 作为项目成员，我希望提交阶段成果，以便支持阶段验收。

**Acceptance Criteria:**

- [ ] 交付物支持文本说明、外部链接和本地文件记录三种类型。
- [ ] 每项交付物保存名称、类型、提交人、提交时间和确认状态。
- [ ] 外部链接必须使用有效的 HTTP 或 HTTPS 地址。
- [ ] 本地文件记录必须展示文件名、大小和访问地址。
- [ ] 已完成阶段不能新增、替换或删除交付物。
- [ ] 在浏览器中验证三类交付物、校验失败和只读状态。

### US-003：提交阶段验收

**Description:** 作为阶段负责人，我希望提交阶段验收，以便确认阶段是否可以结束。

**Acceptance Criteria:**

- [ ] 只有阶段负责人或项目负责人可以提交验收。
- [ ] 必需任务未完成时不能提交，并列出对应任务。
- [ ] 必需交付物未提交时不能提交，并列出对应交付物。
- [ ] 存在未解除阶段阻塞时不能提交，并列出对应阻塞。
- [ ] 满足条件后提交成功，阶段进入待验收。
- [ ] 提交操作生成活动记录。
- [ ] 在浏览器中验证每类阻止条件和成功提交。

### US-004：确认或驳回阶段验收

**Description:** 作为验收人，我希望确认或驳回阶段成果，以便控制项目阶段推进质量。

**Acceptance Criteria:**

- [ ] 项目负责人可处理所有阶段验收。
- [ ] 阶段负责人不能验收自己提交的阶段；由项目负责人提交时，另一项目负责人处理。
- [ ] 确认验收后阶段进入已完成并保存备注。
- [ ] 驳回时必须填写原因，阶段回到进行中。
- [ ] 验收记录保存提交人、验收人、时间、结论和备注。
- [ ] 在浏览器中验证确认、驳回和自验收限制。

### US-005：保护已完成阶段

**Description:** 作为项目负责人，我希望已完成阶段保持只读，以便历史结果可信。

**Acceptance Criteria:**

- [ ] 普通用户不能修改已完成阶段的任务、交付物和验收条件。
- [ ] 页面明确显示已完成和只读状态。
- [ ] 重新打开阶段只能由项目负责人执行并填写原因。
- [ ] 重新打开后阶段回到进行中，原验收记录保留。
- [ ] 重新打开操作生成活动记录。
- [ ] 在浏览器中验证只读、服务端拒绝和重新打开。

## 4. 功能需求

- FR-1：系统必须允许阶段配置必需任务和必需交付物。
- FR-2：系统必须保存交付物类型、提交人、提交时间和确认状态。
- FR-3：系统必须阻止不满足必需条件的阶段提交验收。
- FR-4：系统必须阻止存在未解除阶段阻塞的阶段提交验收。
- FR-5：系统必须限制验收提交和处理权限。
- FR-6：系统必须阻止同一用户提交并确认同一次验收。
- FR-7：系统必须保存完整验收记录。
- FR-8：系统必须限制已完成阶段的普通写操作。
- FR-9：系统必须在重新打开阶段时要求原因并保留历史记录。

## 5. 非目标

- 不实现多级审批、会签或自定义审批流。
- 不实现在线文档协同编辑。
- 不实现电子签名或合规归档。
- 不自动将阶段完成等同于项目完成。

## 6. 技术考虑

- 验收条件校验和阶段状态变更必须在服务端事务中完成。
- 文件型交付物的存储策略必须在技术设计前确定。
- 已完成阶段的只读约束必须覆盖全部相关写接口。

## 7. 成功指标

- 100% 的已完成阶段具有验收记录。
- 不满足必需条件却成功完成的阶段数量为 0。
- 已完成阶段未经重新打开发生写入的数量为 0。
