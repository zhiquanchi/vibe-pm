# PRD-06：项目总览与活动记录

> 版本：v1.0 Draft  
> 日期：2026-08-07  
> 状态：待评审  
> 上游依赖：PRD-01 至 PRD-05

## 1. 概述

聚合前述能力，为项目负责人提供主阶段、并行阶段、任务进度、阻塞、验收和近期变化的统一入口，并为所有成员提供可追溯活动记录。

## 2. 目标

- 项目负责人打开项目后立即理解当前推进状态。
- 所有未解除阻塞和待验收事项可快速进入详情。
- 关键阶段与任务变化形成不可篡改的活动记录。
- 核心页面具备一致导航、URL 和操作反馈。

## 3. 用户故事

### US-001：查看项目开发总览

**Description:** 作为项目负责人，我希望看到项目当前阶段和风险，以便快速判断项目状态。

**Acceptance Criteria:**

- [ ] 总览展示项目名称、负责人、计划日期和整体状态。
- [ ] 项目整体状态由系统根据主阶段状态自动计算（进行中/受阻/待验收/已完成/未开始）。
- [ ] 总览明确展示唯一主阶段及其目标、负责人和计划日期，主阶段在视觉上优先展示。
- [ ] 总览展示全部活动中的并行阶段，并行阶段在主阶段之后展示。
- [ ] 总览展示未完成任务数、受阻任务数和待验收阶段数。
- [ ] 点击指标进入对应的已筛选列表。
- [ ] 数据失败时展示错误信息和重试操作。
- [ ] 在浏览器中验证正常、空项目和接口失败状态。

### US-002：查看项目风险

**Description:** 作为项目负责人，我希望集中查看阻塞和逾期，以便及时处理开发风险。

**Acceptance Criteria:**

- [ ] 风险区展示所有未解除的阶段阻塞和高优先级任务阻塞。
- [ ] 高优先级任务指优先级为"紧急"和"重要"的任务。
- [ ] 逾期阶段和逾期任务具有明确文字标识。
- [ ] 每项风险展示负责人、持续时间和详情入口。
- [ ] 无风险时展示明确的正常状态，不隐藏整个区域。
- [ ] 点击风险进入对应阶段、任务或阻塞详情。
- [ ] 在浏览器中验证阻塞、逾期和无风险状态。

### US-003：查看和筛选活动记录

**Description:** 作为项目成员，我希望查看项目关键变化，以便了解项目如何推进。

**Acceptance Criteria:**

- [ ] 活动记录覆盖阶段结构、状态、主阶段、任务、依赖、阻塞、交付物、验收和成员变化。
- [ ] 每条记录展示操作人、时间、对象和变化摘要。
- [ ] 支持按阶段、事件类型和操作人筛选。
- [ ] 点击记录可进入仍然存在的业务对象。
- [ ] 活动记录不可由普通成员修改或删除。
- [ ] 在浏览器中验证记录生成、筛选和失效对象状态。

### US-004：使用统一导航

**Description:** 作为项目成员，我希望通过稳定导航进入核心页面，以便可靠切换工作上下文。

**Acceptance Criteria:**

- [ ] 项目总览、阶段、我的任务、活动、成员和设置有独立 URL。
- [ ] 当前页面在导航中具有唯一选中状态。
- [ ] 刷新、浏览器前进和后退后保持页面与项目上下文。
- [ ] 未知 URL 显示中文 404 和返回入口。
- [ ] 无权限 URL 显示中文 403 页面。
- [ ] 在浏览器中逐一验证核心路由。

### US-005：获得统一操作反馈

**Description:** 作为用户，我希望每次操作都有明确反馈，以便知道系统正在处理、成功或失败。

**Acceptance Criteria:**

- [ ] 所有异步写操作展示处理中状态并阻止重复提交。
- [ ] 成功操作展示简短中文确认。
- [ ] 失败操作展示可理解的中文错误和可用的重试入口。
- [ ] 暂未开放的可见操作使用禁用状态并说明原因。
- [ ] 菜单、弹层和抽屉支持 Escape 关闭和焦点返回。
- [ ] 前端类型检查、生产构建和关键交互测试通过。
- [ ] 在桌面和窄屏浏览器中完成关键路径验收。

## 4. 功能需求

- FR-1：系统必须在项目总览展示唯一主阶段并视觉优先展示。
- FR-2：系统必须在项目总览展示全部活动并行阶段。
- FR-3：系统必须根据主阶段状态自动计算项目整体状态。
- FR-4：系统必须聚合未完成任务、阻塞和待验收数量。
- FR-5：系统必须展示未解除阻塞和逾期事项。
- FR-6：系统必须记录 PRD-01 至 PRD-06 定义的关键业务变化。
- FR-7：系统必须允许按阶段、事件类型和操作人筛选活动。
- FR-8：系统必须为核心页面提供可直接访问的独立 URL。
- FR-9：系统必须区分 403、404、空数据和请求失败状态。
- FR-10：系统必须为异步写操作提供处理中、成功和失败反馈。

## 5. 页面与路由

- 项目总览：`/projects/:projectId`
- 项目活动：`/projects/:projectId/activity`
- 阶段列表：`/projects/:projectId/stages`
- 我的任务：`/my-tasks`
- 项目成员：`/projects/:projectId/members`
- 项目设置：`/projects/:projectId/settings`

## 6. 非目标

- 不提供故事点、Velocity、燃起图或燃尽图。
- 不实现跨项目管理驾驶舱。
- 不实现邮件、短信、飞书或 Slack 通知。
- 不实现可编辑或可删除的审计日志。
- 首版不实现活动记录订阅、关注、@提及或推送通知。

## 7. 技术考虑

- 总览可以使用聚合 API，避免前端串行请求全部业务资源。
- 活动记录必须来自业务事务，不由前端根据结果临时拼装。
- 日期逾期风险首版按当前日期动态计算，不自动改变阶段状态。

## 8. 成功指标

- 项目负责人在两次点击内进入任一阻塞详情。
- 核心页面直接 URL 访问成功率为 100%。
- 因无响应入口产生的 QA 缺陷数量为 0。
- 核心用户旅程端到端测试通过率为 100%。
