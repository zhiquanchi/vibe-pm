# PRD-03：阶段任务管理

> 版本：v1.0 Draft  
> 日期：2026-08-07  
> 状态：待评审  
> 上游依赖：PRD-01、PRD-02

## 1. 概述

为每个开发阶段提供任务管理能力，并提供跨项目的“我的任务”视图。任务用于表达具体工作，不承担阶段验收语义。

## 2. 目标

- 成员可在阶段上下文中创建、分配和推进任务。
- 用户能在两次点击内找到自己的未完成任务。
- 任务移动、删除和失败回滚具有明确行为。

## 3. 用户故事

### US-001：在阶段内创建任务

**Description:** 作为研发成员，我希望在阶段内创建任务，以便记录需要执行的工作。

**Acceptance Criteria:**

- [ ] 任务包含标题、描述、状态、优先级、负责人和计划日期。
- [ ] 标题和所属项目必填，所属阶段可暂时为空。
- [ ] 新任务默认状态为未开始，默认优先级为"正常"。
- [ ] 优先级可选：紧急、重要、正常、低。
- [ ] 创建成功后任务立即出现在阶段工作台。
- [ ] 创建失败时保留表单内容并展示错误。
- [ ] 在浏览器中验证成功、校验失败和接口失败。

### US-002：查看阶段任务工作台（列表视图）

**Description:** 作为项目成员，我希望按状态查看阶段任务，以便掌握阶段执行情况。

**Acceptance Criteria:**

- [ ] 工作台以列表形式展示未开始、进行中、受阻、待确认和已完成任务。
- [ ] 每行展示任务标题、负责人、优先级、计划日期、状态。
- [ ] 支持按标题、负责人、状态、优先级筛选。
- [ ] 支持按创建时间、计划日期、优先级排序。
- [ ] 点击任务行展开详情或进入任务详情页。
- [ ] 已完成阶段的任务工作台为只读。
- [ ] 在桌面和窄屏浏览器中验证有数据、空状态和只读状态。

### US-003：编辑和推进任务

**Description:** 作为任务负责人，我希望更新任务信息和状态，以便反映实际工作进展。

**Acceptance Criteria:**

- [ ] 有权限用户可以编辑任务字段和状态。
- [ ] 任务状态转换必须符合总纲定义的状态转换表。
- [ ] 非法状态转换被服务端拒绝并返回明确错误提示。
- [ ] 状态变化记录操作人、时间、原状态和新状态。
- [ ] 同一写操作进行中时禁止重复提交。
- [ ] 写操作失败时任务恢复原状态并展示错误。
- [ ] 观察者和已完成阶段不展示可写操作。
- [ ] 在浏览器中验证编辑、状态推进、权限和错误回滚。

### US-004：移动和删除任务

**Description:** 作为项目成员，我希望移动或删除任务，以便修正任务规划。

**Acceptance Criteria:**

- [ ] 未完成任务可移动到另一个未完成阶段或设为未规划。
- [ ] 将任务移出已启动阶段时必须填写原因。
- [ ] 删除任务前展示任务标题并要求确认。
- [ ] 被其他任务依赖时阻止删除，提示"该任务被 X 个任务依赖，请先解除依赖关系"。
- [ ] 是阶段验收必需任务时阻止删除，提示"该任务是阶段验收必需项，请先调整验收条件"。
- [ ] 移动和删除生成活动记录。
- [ ] 在浏览器中验证移动、删除、阻止删除和失败回滚。

### US-005：查看我的任务

**Description:** 作为研发成员，我希望集中查看分配给我的任务，以便安排当前工作。

**Acceptance Criteria:**

- [ ] 默认展示当前用户跨项目的未完成任务，按计划日期升序排序。
- [ ] 每项任务展示项目、阶段、优先级、状态和计划日期。
- [ ] 支持按项目、阶段、状态和优先级筛选。
- [ ] 优先级显示为中文：紧急、重要、正常、低。
- [ ] 逾期和受阻任务具有文字与视觉标识。
- [ ] 点击任务可打开详情并返回原筛选状态。
- [ ] 在浏览器中验证筛选、空状态和任务更新。

## 4. 功能需求

- FR-1：系统必须允许任务归属于一个项目阶段或保持未规划。
- FR-2：系统必须为任务保存标题、描述、状态、优先级、负责人和计划日期。
- FR-3：系统必须限制已完成阶段中的任务写操作。
- FR-4：系统必须在任务移出活动阶段时要求填写原因。
- FR-5：系统必须在删除任务前要求确认。
- FR-6：系统必须阻止删除被依赖或为验收必需的任务。
- FR-7：系统必须记录任务创建、移动、删除和状态变化。
- FR-8：系统必须提供当前用户跨项目的未完成任务视图。
- FR-9：系统必须为失败的任务写操作恢复原状态。
- FR-10：系统必须校验任务状态转换符合总纲状态转换表。
- FR-11：系统必须支持任务优先级国际化（中文默认：紧急/重要/正常/低）。

## 5. 页面与路由

- 阶段任务：`/projects/:projectId/stages/:stageId`
- 未规划任务：`/projects/:projectId/tasks?stage=unplanned`
- 我的任务：`/my-tasks`

## 6. 非目标

- 不实现子任务、周期任务或任务模板。
- 不实现故事点、Velocity 或固定工时填报。
- 不实现代码提交、PR 或 Issue 自动关联。
- 不在本 PRD 中实现任务依赖和阻塞规则。
- 首版不实现批量操作（批量移动、批量修改优先级、批量分配负责人）。
- 首版不实现"我的任务"今日计划视图或自定义默认视图。
- 首版不实现看板视图，看板作为 v1.1 或 v2.0 功能。

## 7. 成功指标

- 成员从项目任意页面进入自己的未完成任务不超过两次点击。
- 任务写操作失败后出现错误状态残留的数量为 0。
- 已完成阶段发生普通任务写入的数量为 0。
- 非法任务状态转换成功数量为 0。
- 被依赖或验收必需的任务删除成功数量为 0。
