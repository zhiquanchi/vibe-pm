## Context

后端为 FastAPI + SQLAlchemy 2.0，现有表：projects、profiles、project_members、stages、tasks、task_dependencies、task_blockers、stage_blockers、scope_changes、sprint_snapshots、project_activities。AI 副驾驶通过调用 AI 模型 API（如豆包）生成摘要、分析和建议。

## Goals / Non-Goals

**Goals:**

- 新增 AI 项目摘要 API：生成项目状态摘要
- 新增 AI 阶段风险分析 API：分析阶段推进风险
- 新增 AI 个人行动建议 API：根据用户任务生成个人行动建议
- 新增 AI 项目管理问答 API：自然语言询问项目问题
- 新增 AI 项目近期变化回顾 API：总结指定时间范围内的项目变化

**Non-Goals:**

- 不接入 GitHub、GitLab、Gitee、CI/CD 或代码质量平台数据
- 不读取或编辑在线文档内容
- 不向飞书、Slack、企业微信、邮件或短信发送消息和通知
- 不自动创建、修改、移动、删除或分配任务
- 不自动修改阶段、依赖、阻塞、交付物或验收条件
- 不代替用户提交、确认或驳回阶段验收
- 不预测精确完成日期或自动生成项目排期
- 不进行成员绩效评价、工作量排名或人员利用率评价
- 不回答与当前项目管理上下文无关的通用问题

## Decisions

### D1：AI 项目摘要 API

`POST /api/projects/{id}/copilot/summary` 返回：
- 当前主阶段、活动中的并行阶段和各自负责人
- 主阶段优先展示和分析
- 逾期事项、未解除阻塞、未完成关键依赖和待验收阶段
- 不超过五项按优先顺序排列的建议行动
- 每项事实或风险提供对应项目记录入口

### D2：AI 阶段风险分析 API

`POST /api/projects/{id}/stages/{sid}/copilot/analysis` 返回：
- 已记录事实、AI 推断和建议行动
- 未完成前置依赖、活动阻塞、逾期任务、无人负责事项和验收条件缺口
- AI 无法判断的事项标记为"信息不足"
- 建议不得自动改变阶段或任务状态

### D3：AI 个人行动建议 API

`GET /my-tasks/copilot/advice` 返回：
- 根据当前用户的未完成任务生成个人行动建议
- 优先考虑受阻任务、逾期任务、主阶段任务、未满足依赖和临近验收条件
- 每项建议说明推荐原因并链接到对应任务或阶段
- AI 不得替用户修改优先级、负责人、状态或计划日期

### D4：AI 项目管理问答 API

`POST /api/projects/{id}/copilot/chat` 返回：
- 用户用自然语言询问项目问题
- 回答基于实时项目数据生成
- 回答中的关键事实提供可访问的项目记录入口
- 问题超出项目数据、当前权限或副驾驶职责时，AI 明确说明无法回答的原因
- AI 不得声称已经执行任何实际项目操作

### D5：AI 项目近期变化回顾 API

`GET /api/projects/{id}/copilot/changes?range=24h|7d|30d` 返回：
- 回顾指定时间范围内的项目变化
- 区分已完成事项、仍未解决事项和新出现风险
- 每项变化可进入对应活动记录或业务对象
- 时间范围内没有活动时展示明确空状态

### D6：权限与决策责任

- AI 只能读取当前用户有权访问的项目数据
- AI 明确区分项目事实、推断和建议
- AI 不得提交、确认或驳回阶段验收
- AI 不得自动创建、修改、移动或删除任何项目对象

## Risks / Trade-offs

- [AI 生成可能影响性能] → 使用异步生成或缓存
- [AI 输出可能不准确] → 明确标注事实和推断，提供项目记录入口

## Migration Plan

无数据迁移。`init_db` 的 `create_all` 自动创建新表（如有）；现有库与数据完全不动。回滚 = 删除新路由与服务，不影响存量功能。

## Open Questions

- 后续版本是否允许用户确认 AI 建议后创建任务或阻塞记录？
- 是否需要跨项目 AI 工作台，为项目负责人汇总多个项目的风险？
- 是否允许项目负责人配置副驾驶重点关注的规则和阈值？
- AI 对话和生成结果需要保留多久，哪些角色可以查看历史记录？
- 用户是否可以对 AI 结论标记"有帮助""不准确"或"已处理"，用于后续改进？
